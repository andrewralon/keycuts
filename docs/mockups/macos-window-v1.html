keycuts on macOS: the window, ⌘ keys and menus (v1)

Phase 5.1, 5.2 and 6.1 of the macOS plan. The window keeps the folder-tab bar; macOS's traffic lights take the place of the Windows caption buttons, at the left. Everything else on the screens is unchanged. Drawn at 1:1 in the style guide's sizes with the system font (San Francisco), which AppFontFamily already picks on macOS.

  • Traffic lights are macOS's own (extended client area, Phase 0.7), 20 from the left edge and centered in the 48 bar. Zoom is always off (gray), on every screen: no zoom, no full screen, as "never maximized" on Windows. Close and minimize work as usual.
  • Then the keycap and keycuts, 16 after the lights, then 24 to the first tab, as on Windows. The bar keeps the same MainWidth: the lights at the left take about what the caption buttons took at the right, so the empty, draggable bar now runs to the right edge.
  • No Windows caption buttons, no window menu. Dragging the bar moves the window; double-clicking it does what the system setting says, except zoom.
  • Tooltips and accelerators read ⌘1, ⌘2, ⌘3: "manager (⌘2)".

The style guide's "Keys" section gets a macOS line: key names as macOS writes them, with the symbols ⌃ ⌥ ⇧ ⌘ in that order and no plus signs (⇧⌘E). Tooltips put the key in parentheses as on Windows.

  • The app menu (left) holds About, Settings and Quit, as the plan says, plus the standard Hide items macOS expects. Menu items are in Title Case where macOS puts its own (About, Hide Others, Quit) and in keycuts' sentence case elsewhere ("New keycut…").
  • The menu bar icon (right) is the app icon’s keycap in full color, the one chosen in Settings, not an outline. Its menu: Run… opens the Run box and shows the hotkey; New keycut… opens the Creator, empty; Manager; Settings…; Quit keycuts.
  • Lifetime (6.1): closing the window (red light, ⌘W) leaves keycuts in the menu bar; the Dock icon shows only while a window is open. Quit is in both menus.
